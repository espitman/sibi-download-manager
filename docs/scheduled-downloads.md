# Scheduled downloads

Settings → Scheduled downloads controls a separate daily Resume all / Pause all pair. Its times use the phone's current local time zone and follow clock or time-zone changes. It is off by default; saving Off cancels both alarms. The alarms are restored after device boot. The editor uses scrolling hour and minute wheels and explains when Android's precise-alarm access is unavailable. At each boundary it invokes the same bulk commands as the Downloads controls; per-download schedules continue to govern whether a queued file may actually start.

Add and Download details allow a one-time start with an optional end, or a daily start/end window. A daily window may cross midnight. A one-time window stores absolute instants; a daily window stores wall-clock minutes and the time zone selected when the rule was created. Editing a daily rule preserves that time zone. Removing a rule returns a schedule-paused download to the queue; a manual pause remains paused.

The queue admits only downloads whose schedule is currently open, and still applies Wi-Fi-only and simultaneous-download settings. At a closing boundary, an active transfer is paused with its partial file intact. The next opening boundary requeues only records marked as paused by the schedule. Completed, cancelled, and failed downloads are not restarted by a schedule. A one-time end that passes before completion leaves the download paused until the user removes or edits its schedule.

Schedules live in the versioned downloads database. Process start, clock/date/time-zone broadcasts, and scheduled alarms reconcile the queue. After device boot, the receiver restores pending records and alarms without directly starting a `dataSync` foreground service; the next alarm handles admission. On Android 12 and later, exact timing requires the Alarms & reminders special access. The schedule editor links to that system setting when access is absent. Without it, Android may deliver the fallback alarm late. A scheduled queue item remains visible while waiting.

Coverage includes one-time boundaries, overnight daily windows, fixed-zone behavior, manual-pause preservation, database migration and reopening, boot alarm planning, queue admission, and device tests that verify a scheduled local HTTP transfer stays queued until its alarm and pauses with a partial offset at its end boundary.
